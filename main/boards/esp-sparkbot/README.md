# ESP-SparkBot 320×240 线控面板

界面来自 Figma 文件 `K0CEJFaZBgQfmFNGyxD9zF`。`ControllerDisplay` 在原有
`SpiLcdDisplay` 之外创建独立的常规屏幕，保留小智的表情、字幕、配网和升级界面。

## 显示切换

- `Idle`：显示常规控制面板，保留进入语音前的页面。
- `Connecting / Listening / Speaking`：显示原有小智界面。
- 启动、激活、配网、升级、音频测试和错误状态：保留系统界面。
- 常规界面仍显示通知和系统告警；主题更新作用于原有对话屏幕。

## 六键操作

按键位和引脚参考本地 `z_XKQ` 分支，使用电容按键，不是坐标触摸屏。

| 按键 | 主页 | 其他页面 |
| --- | --- | --- |
| 确认（bit 0） | 激活选中项 | 进入或确认；温度编辑页进入保存确认 |
| 菜单（bit 1） | 打开菜单 | 打开菜单 |
| 下（bit 2） | 下一个选中项 | 下一个选中项；温度参数翻页；编辑值减小 |
| 关机（bit 3） | 返回主页 | 返回主页，不直接关闭设备 |
| 返回（bit 4，原模式键） | 保持主页 | 返回上一级 |
| 上（bit 5） | 上一个选中项 | 上一个选中项；温度参数翻页；编辑值增大 |

长按确认 1.5 秒进入/切换语音；保留 BOOT 单击原有的小智操作。上下键支持长按重复。
选中框始终可见。主页通过“设备开机/设备关机”控制设备，通过“语音控制”唤醒小智。
语音期间确认键沿用现有对话切换逻辑；返回、菜单、关机键结束对话，回到先前页面、菜单、主页。
启动、配网和升级等系统状态不会因普通导航键被退出。

## 硬件与协议

| 功能 | 配置 |
| --- | --- |
| 触摸按键 | I2C1，SDA=GPIO6，SCL=GPIO5，INT=GPIO4，地址0x28 |
| 触摸芯片 | CAP1298（产品0x71、厂商0x5D），否则使用参考分支的 Cypress 兼容读法 |
| 蜂鸣器 | GPIO37，LEDC低速timer1/channel1，2930 Hz，单次80 ms |
| 485 | UART1，TX=GPIO11，RX=GPIO10，RTS/DE=GPIO9，9600/8N1，半双工 |

CAP1298 配置和 Modbus 寄存器映射来自 `z_XKQ`，实现增加了按键去抖、I2C失败处理、
可复用蜂鸣器定时器、串行请求、接收拼包、CRC/地址/功能码检查、超时和写后回读。
驱动独立任务不持有 LVGL 锁；按键通过 `Application::Schedule` 交给主任务。

新版为单设备界面，固定轮询地址1，显示“当前设备”。没有响应时显示未连接，
不会发送控制写入。每次读取寄存器0–49；已核实的映射如下：

| 寄存器 | 含义 |
| --- | --- |
| 0 | 开关 |
| 1 | 模式：0制热，1制冷，5送风，6除湿 |
| 2 | 设定温度，0.1°C |
| 3 | 出水温度，0.1°C |
| 4 | 回水温度，0.1°C |
| 5 | 环境温度，0.1°C |
| 6 | 故障码 |

控制通过功能码0x10写寄存器0–2，然后读取并核对。界面显示真实回读值，不把排队当成执行成功。
温度范围沿用参考分支的模式说明：制冷5–25°C、制热25–55°C；切换模式时将设定温度限制到新范围。
参考分支没有完整说明其他模式的温度范围，因此其他模式暂不发送温度修改；切换至送风/除湿时保留已有设定值。

语音工具 `self.ac.power_on / power_off` 控制地址1；`get_state / set_temperature / set_mode`
同样限定为设备地址1。工具返回排队结果，最终执行结果通过 `get_state` 获取。

## 已知范围

按2026-10-10的“单设备六键 / 静态界面”更新了40个设计页面/补充状态，移除旧设备选择页。
温度变化共用编辑页面；语音和配网使用工程真实流程，
不播放设计中的示例识别、配网成功或设备数据。温度参数按热泵协议显示环境、回水、出水温度。

风速、睡眠/节能/联动、设备端日程、单独传感器状态没有已验证的寄存器，页面会提示未接入。
日程编辑仅为界面预览，不保存、不自动执行；历史故障目前显示暂无记录。
语言由固件配置决定，时间使用系统联网校时。此处不宣称这些扩展功能已经接入设备。

## 资源与验证

生成文件：`controller_pages.inc`、`controller_icons.c`、`controller_fonts.c`。
SVG均从设计资源下载并按原始尺寸转换，固件不访问 Figma；字体使用4bpp子集节省Flash。
源上下文、原图、生成脚本、字体许可证位于 `scripts/controller_ui/`。
`preview.png` 是设计数据的桌面布局预览，不是实机截图。

在 ESP-IDF 环境执行 `idf.py reconfigure build`。新增文件由既有板级 CMake glob 收集。
协议和状态选择回归检查：

```sh
xtensa-esp32s3-elf-g++ -std=c++17 -fsyntax-only -I. -Imain scripts/controller_ui/test_protocol.cc
```

资源再生成需要 Python、Pillow、resvg-py、clang-format，以及本机 Noto Sans SC 字体；生成脚本顶部可调整字体路径。
手写代码和生成代码采用展开格式，生成器使用 `scripts/controller_ui/.clang-format` 保持可读性。
固件编译不需要这些桌面依赖。当前尚未烧录实机，需要验证按键极性、蜂鸣器、485 DE方向、
实际设备地址/温度范围，以及唤醒和结束对话的显示切换。
